# 构图两个 P1 的修复验证

验证日期：2026-09-09。比较基线：`668f17ea4408878316ed5f7322bdd8a01788e9c5`；修复代码位于当前分支工作区。

## 修复结果

- 构图准入先于线程提交；专用执行器与内置算法子进程不占普通请求的默认线程池。默认每个服务进程并发 1，每个用户并发 1。
- 活动任务重复提交返回相同 `build_id`；参数冲突返回 409，超额新任务返回 429，不排队或自动重试。已完成图仍可复用。
- HTTP 断线不丢失服务持有的任务。超时、关闭和重启均先确认工作进程退出，再释放任务名额和数据集锁；成功结果原子提交，失败不增加修订号。
- 候选索引按节点、关联边和表构建，保留顺序、自环和平行边语义；同一图版本复用候选，接受转换后失效。构图各阶段共用截止时间，预算耗尽不会被写成无效候选或负面领域经验。
- 前端识别明确的容量拒绝，关联构图尝试；旧失败轮询不会丢弃新的成功结果。

配置与接口细节见 [构图文档](GRAPH_CONSTRUCTION.md)。

## 故障场景与证据

已覆盖 32 个同数据集请求只运行一次、用户/全局容量限制、默认线程池缩小到 2 时真实 HTTP 查询仍在构图阻塞期间完成，以及来源校验、进程启动和发布失败后的重试。进程测试包含忽略终止请求、服务关闭、杀死旧服务后回收真实孤儿进程及其后代、继承的数据集锁、保留已提交图，以及无法确认恢复时继续允许状态读取。

本地原始证据位于 `output/reviews/construction-p1-fix-20260909/`：`baseline.xml`、`regression.xml`、`fault-regression.xml` 和 `benchmark.json`；该输出目录不随源码提交。

真实模型供应商调用和生产多实例压测未在本次执行；LLM 路径由已有脚本化模型测试覆盖。建议保持默认构图并发 1，按部署实例总数和实际 CPU、内存容量评估后再提高。
