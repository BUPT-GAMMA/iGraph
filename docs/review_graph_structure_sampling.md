# 图谱结构抽样优化验证

日期：2026-09-15。基于 dev `5e9b315`。

## 问题与目标

旧的两层智能抽样会保留社区代表、漏掉其邻居或连接路径。在用户提供的 `cora.pt` 上，原图没有孤立节点，画布却出现 77 个孤立点。只恢复单个中心的 BFS 虽能消除散点，却会偏向某个局部区域。

此次目标是保持主要连通块的规模比例、覆盖主要社区、保留真实连接和关键桥接边，并继续使用 180 节点 / 400 边的 SVG 上限。

## 实现策略

1. 后端和前端先识别已加载数据中的连通块，按规模分配节点预算。非单点组件首次分配至少两个位置，避免把每个小组件都画成一个点；真正的孤立点集中分配预算，并兼顾其类型比例。
2. 在每个被选中的组件内，从枢纽或用户指定节点出发，构建确定的 BFS 路径树。社区或类型代表只有在连接路径也能放入预算时才加入。随后沿真实邻居扩展，优先补足类型、社区配额。
3. 连通性优先于严格的类型比例。普通代表路径通常最多使用该组件约 65% 的节点预算，余下位置用于邻域结构；显式用户目标优先保留。小预算组件可以使用全部预算保留路径。
4. 边数超过预算时先保留显式高亮边和连接骨架，再补充其余边，防止密集或平行边挤掉连接不同区域的桥。
5. 对历史部分图中“局部没有边、但上游声明有度数”的节点，不优先把它们作为自动抽样代表；显式搜索或选择仍可保留。此处理不会凭空补边，也无法恢复上游已经漏掉的路径。

## Cora 对比

同一文件：2,708 节点，5,278 条无向边，78 个连通块，0 个孤立点；最大连通块 2,485 节点，占 91.8%。主要社区在本次对比中定义为对完整图做固定种子的 Louvain 分区后，规模至少 50 的社区，共 16 个。

| 指标 | 旧 BFS 局部预览 | 出问题的两层抽样 | 优化后 |
| --- | ---: | ---: | ---: |
| 画布节点 | 180 | 180 | 180 |
| 画布边 | 354 | 157 | 249 |
| 孤立点 | 0 | 77 | 0 |
| 最大连通块节点 | 180 | 103 | 166 |
| 最大连通块占比 | 100% | 57.2% | 92.2% |
| 覆盖主要社区 | 9 / 16 | 未单独计数 | 16 / 16 |

优化后的画布有 8 个连通块：一个 166 节点主组件和七对相连节点。它保留原图大组件与小组件的大致占比，但没有声称展示全部 78 个组件。

后端的 800 节点候选图由 84 个孤立点改善为 0 个孤立点，主组件为 734 个节点，占 91.75%。新前端对旧后端的历史 800 节点结果也能改善到 0 个孤立点，但结构比例不如重新获取的新结果，因此应重新加载图谱。

旧 BFS 代码包含随机打乱扩展顺序，表中对应本次复现样本，不保证每次旧版本结果的边数完全相同。新算法在相同输入与参数下保持确定性。

## 验证

- 完整前端：35 个文件、326 项测试通过。
- 后端相关回归：28 项测试和 19 项子测试通过，覆盖结构抽样、社区着色、度数、远端预算、只读图工具和并行计算。
- 新增测试覆盖组件比例、真实孤立点及其类型、历史部分图残留、稠密区域之间的桥接边，以及前端最终边截断后的连通性。
- TypeScript 和 Vite 生产构建通过；保留既有主包体积警告。
- 真实浏览器实际渲染 Cora 180 节点、249 边。亮暗主题正常；悬浮枢纽 163 时有 28 条关联边高亮，点击选择正常。
- 20,000 节点 / 100,000 边压力输入：首次索引和选点约 209.5 毫秒，生成预览约 4.5 毫秒。180 次交替缩放的 95% 帧间隔约 12.5 毫秒、最大约 25.4 毫秒；未记录到 50 毫秒以上主线程长任务，可见标签随视角在 8～30 个之间变化。
- 本地 frontend 和 graph-engine-api 镜像已更新；六个 Compose 服务均为 healthy。

## 剩余边界

抽样不能同时精确保留所有组件、社区比例、度分布、聚类系数和路径长度。这里优先保证可见结构有真实连接，并接近组件比例、覆盖主要社区；它仍是部分图。节点大小继续使用原图度数，不能用画布上可见的边数替代全图度数。

输入已在上游截断时，只能保留现有路径；超小节点/边预算或过多显式高亮也可能无法容纳完整连接。大图首次索引仍有同步计算成本，但缩放不会重复索引和选点。性能结果来自本机，并非所有设备的保证。
