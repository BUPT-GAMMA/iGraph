# 独立对话、个人数据集与项目删除

## 使用方式

- 全局「新建任务」打开独立对话。项目旁的「＋」在指定项目中新建对话。
- 「项目」列出用户创建的项目及所属会话；「最近任务」仅列出独立对话，按活动时间排序。
- 独立对话的输入框可以打开个人数据集库。同一账号可复用个人数据集，新对话需要主动选择。项目对话使用项目数据集和项目默认选择。
- 独立对话的 Graph ML 面板只读取当前会话的结果；项目会话可以进行项目对比。
- 删除项目会停止所属任务，删除项目会话、图和上传文件、项目数据集及归属可验证的模型文件。个人数据集、其他项目和已下载文件保留。

## 归属和接口

`project_id` 省略或为 `null` 时表示独立对话／个人数据。查询个人数据始终同时匹配用户和空项目归属。

| 接口 | 行为 |
| --- | --- |
| `POST /api/sessions` | 可空的 `project_id`，项目内创建仍验证项目和数据集归属 |
| `GET /api/personal-datasets` | 当前用户的个人数据集 |
| `POST /api/personal-datasets` | 复用项目上传校验，支持显式应用到当前独立对话 |
| `PATCH /api/personal-datasets/{id}` | 重命名个人数据集 |
| `DELETE /api/personal-datasets/{id}` | 删除个人数据集，活动任务或后台作业仍在使用时返回冲突 |
| `DELETE /api/projects/{id}` | 必须提交 `{"conversation_action":"delete"}`；可靠接受返回 `202`，已完成返回 `200` |
| `GET /api/projects/{id}/deletion` | 返回 `delete_status` 和资源清理状态；投递暂时失败时保留 `delivery_pending` |

旧 `move_to_general` 删除请求返回 `PROJECT_DELETE_ACTION_CHANGED`（409），缺少删除动作返回 422。跨范围会话移动返回 `SESSION_MOVE_UNSUPPORTED`（409）。

## 删除的执行边界

完整流程要求现有 `IGRAPH_RUN_CANCEL_ENABLED=true` 及服务凭据配置。沿用 BFF、Agent Runtime、Graph Engine 和 PostgreSQL，不新增部署服务。

1. BFF 原子保存项目删除意图，关闭项目的新建、上传、发送和审批入口，立即取消所属准备请求。
2. Runtime 在现有执行控制表中保存 `project` 删除记录和 `member` 成员记录。项目删除和成员登记使用同一个项目锁；实际执行仍使用会话控制边界。
3. 完整分页读取历史会话，并合并正在创建中的会话预留记录。向全部成员登记会话删除，停止当前执行及历史后台作业。
4. 确认准备、原生创建、Agent 和子作业退出后，删除会话、图和附件；原生创建计数与执行者租约防止迟到写入。Graph Engine 的本地删除标记阻止已经通过远端准入的迟到请求重新创建图状态。
5. Graph Engine 按可验证的会话成员和模型归属记录删除模型；BFF 删除项目数据集和元数据。文件删除失败时保留待确认状态，后台继续重试。

BFF 在运行时重试尚未投递的删除标记；Runtime 的扫描器在重启后恢复未完成清理。前端收到接受响应后及时移除项目及会话，清理所属草稿和连接；仅当前页面属于被删除项目时切回新对话。

关闭取消能力的兼容环境仅支持空闲项目删除，无法安全停止执行时明确返回冲突。发布时使用完整版本组合；BFF 的 JSON 元数据延续现有单写实例部署约束。

## General 迁移

先让旧版 General 中的 Agent 和后台作业结束，再升级服务。迁移同时匹配系统默认标记和确定性的项目 ID；用户自行创建的同名 General 保持普通项目身份。

在使用实际部署配置、可访问 Runtime 和 Graph Engine 的 BFF 环境中运行：

```bash
# 只预检查，不修改归属或文件
python -m backend.migrate_general

# 先备份，再迁移；可重复运行
python -m backend.migrate_general --apply
```

前端读取项目列表时，也会为当前用户执行相同的可恢复迁移。尚未结束的旧任务返回 `GENERAL_MIGRATION_ACTIVE`，保留原数据。升级前预检查和结束旧任务可避免首次打开页面时等待迁移。

备份位于项目元数据同级的 `migrations/general-v1/<用户摘要>/`，包含原项目、数据集元数据、相关会话详细状态和 `manifest.json`。首次备份保留，重试沿用原始成员清单。CLI 将完整迁移及未归属模型目录清单写入 `migrations/general-v1/report.json`。

迁移仅清除会话／数据集的项目归属和系统 General 元数据，保留 ID、消息、当前数据集选择、图版本、模型和源文件路径。旧全局默认数据集停止生效。图模型归属根据可验证的会话信息补齐；无法确认归属的遗留目录保留原文件并列入报告。

浏览器将旧 General 页面链接转到独立草稿入口。旧草稿迁入个人草稿键；发生冲突时两份内容都保留，页面提供恢复入口。本地存储不可用时保留原内容，不覆盖后续编辑。

升级前应保留数据目录和数据库备份。若需要回退代码，应连同迁移前元数据和会话状态恢复；新版本中创建的独立对话及个人数据需要先导出保留。整个迁移禁止使用普通项目删除接口。

## 回归验证

复用现有 pytest、Vitest 和 Playwright，不更改 CI 结构或覆盖率政策。新增回归覆盖个人／项目数据隔离、General 重试和草稿冲突、项目删除与创建并发、真实流式／审批／训练取消、完整分页和重启清理、迟到图创建与遗留模型保护。

本地运行 Python 全量回归时可显式设置 `IGRAPH_RUN_CANCEL_ENABLED=false`，避免开发 `.env` 改变普通单元测试配置；真实取消链路 fixture 会单独开启能力。提供 `IGRAPH_CONTROL_TEST_DATABASE_URL` 时，现有 fixture 使用隔离 PostgreSQL schema 验证控制并发和完整 HTTP 链路。
