# 预置图与示例问题

部署启动时，Graph Engine 将随源码提供的三个 NPZ 快照安装到持久化数据卷和服务器数据集目录。安装校验 SHA-256，重启不覆盖已保存的用户版本，也不调用模型重新构图。首页“从这里开始分析”可创建当前用户自己的示例项目；点击示例问题会选中对应图并开始提问。项目空会话也提供对应问题。

| 示例 | 数据来源 | 节点 | 关系 |
| --- | --- | ---: | ---: |
| 金融股权穿透分析 | 用户已保存的金融三表 PK/FK 图，原始持股记录保留为节点 | 19,436 | 26,872 |
| 化学分子性质分析 | 五份 CSV、分子结构与已报道实验条件 | 22 | 48（24 条无向化学键） |
| 文学人物关系网络 | 用户提供的完整《天龙八部》TXT，deepseek-v4-pro 处理 106/106 分块 | 304 | 715 |

示例卡片、默认项目与数据集依次命名为“金融股权穿透分析”“化学分子性质分析”和“文学人物关系网络”；英文界面对应 Ownership Look-Through Analysis、Chemical Molecular Property Analysis 和 Literary Character Network。升级时自动更新已有示例的旧默认名称，保留用户自定义名称、图内容和历史版本。

示例问题支持按顺序继续：一题成功回答后，空白发送框会以浅灰色显示下一题及题号；在输入框按 Tab，或点击“下一示例”，只填入问题，再按回车发送。最后一题后不再提示。提示跟随界面语言，并从当前会话的已完成问答恢复进度；输入已有草稿、上传附件、运行中、失败或取消时不会覆盖用户输入或提前推进。

小说预置资源位于 `graph_engine/resources/tianlongbabu/`，manifest 保存原始文件哈希、图快照哈希和完整分块处理记录。预置资源包含图、清单及构图数据源所需的压缩源文件，不包含模型凭据。图中人物名称按原文抽取，保留来源分块；当前没有自动合并“乔峰/萧峰”等别名，也不保证模型抽取的关系语义完全准确。金融快照中超额持股、覆盖不足和循环持股保留原始事实，由分析工具报告。

旧“金融股权示例”已退出默认示例列表，启动不再安装该旧预存图。金融风控及其三张 CSV 原始示例数据继续提供。升级保留已有用户项目、历史会话和数据版本。


## 帮助中的用户案例视频

“帮助”中的“用户案例”与“使用流程”“图分析计算工具”“图学习模型”并列。每个案例按图介绍、四个当前示例问题、应用价值和演示视频排列；顶部可直接跳转到对应案例。页面文案跟随界面语言，录制视频为中文。案例名称、介绍和问题复用首页的示例目录，不单独维护另一套问题。

| 示例 | 随源码提供的视频 |
| --- | --- |
| 金融股权穿透分析 | `frontend/public/media/user-cases/financial-risk.mp4` |
| 化学分子性质分析 | `frontend/public/media/user-cases/molecular-graph.mp4` |
| 文学人物关系网络 | `frontend/public/media/user-cases/demi-gods-and-semi-devils.mp4` |

三个 MP4 来自用户提供的“金融风控.mp4”“分子图.mp4”“天龙八部.mp4”，同目录 JPG 为视频截帧封面。资源随 `frontend/Dockerfile` 打包进镜像，首次部署无需另行上传、登录视频站或访问外部视频服务。

播放器支持原生播放、暂停、拖动进度与全屏；使用 `preload="none"`，打开帮助时仅加载封面，点击播放后才读取视频。播放另一段会暂停上一段，切换帮助栏目或关闭帮助会停止播放。“打开视频”可单独打开同一部署上的 MP4。Nginx 直接提供媒体文件及 HTTP Range 分段请求，找不到资源时返回 404。

已有部署更新本功能时，保留原 `.env` 与数据卷，在服务器项目目录执行：

```sh
docker compose -f compose.yaml -f compose.server.yaml build frontend
docker compose -f compose.yaml -f compose.server.yaml up -d --no-deps frontend
docker compose -f compose.yaml -f compose.server.yaml ps frontend
```

如果原部署指定了 Compose 项目名，上述三条命令也须使用相同的 `-p` 项目名。仅使用 `compose.yaml` 的部署可移除覆盖文件参数。构建完成后刷新浏览器，打开“帮助 → 用户案例”，分别点击三个视频并拖动进度验证。分子示例第三问的更新位于后端，已有部署还须按原部署方式重建并启动 `backend`。

替换视频时保留文件名或同步更新 `HelpUserCases.tsx` 中的映射，同时更新对应封面并重建前端镜像；推荐浏览器兼容的 H.264 MP4。视频是演示录制，后续示例问题的文字更新不会自动重录视频内容。

## 重新生成小说预置资源

在部署环境配置 `GRAPH_CONSTRUCTION_API_KEY` 和 `GRAPH_CONSTRUCTION_BASE_URL`（OpenAI 兼容基础地址）；这些值不会从构图请求的 options 接收。TXT 页面默认选择 `deepseek-v4-pro`，可选模型由 `GRAPH_CONSTRUCTION_MODELS` 限定。正文支持 UTF-8、GB18030/GBK 和带 BOM 的 UTF-16。

```sh
python scripts/prepare_novel_preset.py /path/to/天龙八部.txt --work-dir /path/to/private-checkpoints
```

脚本使用完整输入、12,000 token 分块、300 token 重叠和最多 3 路抽取；缓存绑定模型、完整提示和输出预算，可在失败后续跑。工作目录包含私有抽取结果，应保留在部署环境中，不提交到仓库。生成后重新构建服务器 Compose 镜像即可将快照随系统发布。

普通用户上传构图与内置快照安装是两个入口。普通构图先生成待保存草稿，可预览与优化；点击“保存构图结果”后，才可选择该图进入分析。


## 人物关系的人工补录（2026-10-11）

预置图在原始 304 个节点、791 条抽取关系的基础上，通过前端构图工作区补录并手动保存了四条关系：无崖子→王夫人（父亲）、李秋水→王夫人（母亲）、李秋水→梦姑（祖母）、虚竹→梦姑（丈夫）。该修订2为 304 个节点、795 条关系；当前修订3见下文。补录没有增加重复人物节点。

补录依据及日期保存在每条边的 provenance 和资源目录 manual-corrections.json 中。资料确认王夫人即李青萝，梦姑即西夏银川公主（李清露）。出处：[角色列表](https://zh.wikipedia.org/wiki/天龙八部角色列表)、[李秋水人物资料](https://jinyongx.com/data/1492.html)。这些是外部资料人工补充，不得冒充原始 TXT 自动抽取或伪造来源分块。

“创建你的图”→“查看构图”→“添加节点／添加关系”可继续补充遗漏信息。先应用并预览，再保存到数据集；刷新后保存的版本仍可使用。示例 NPZ 与校验清单已同步，首次部署会安装修正图。安装器仍不会覆盖已有用户图，已有部署需要显式核对和迁移示例文件。

升级已有部署时，先备份并核验预置文件，再更新服务器示例文件；随后从首页重新点击“使用示例图”。同一文件的新版本会创建新的项目引用并设为默认，同一版本重复打开仍保持幂等；旧引用不会被静默改绑。历史会话的文字仍保留，继续分析请使用新会话和新版本图。


## 亲缘纠错与推断（修订3）

本修订审核150条关系断言，纠正关系方向、亲属称谓和剧情误认，合并80条重复断言，发布图为304节点、715条关系。逐项前后对照保存在 `graph_engine/resources/tianlongbabu/kinship-corrections.json`；原106个文本分块及四条补录的出处仍可追溯。

已核实关系约定为“源人物是目标人物的该角色”：生父/生母→孩子、师父→弟子。段正淳→段誉为名义父亲，段延庆→段誉为生父；钟万仇→钟灵为名义父亲，乔三槐→乔峰为养父。早期误认兄妹单独标记。王夫人→慕容复纠正为舅母，段延庆与刀白凤的“夫妻”纠正为一夜情。

`inspect_kinship` 从当前会话图读取 `properties.relationship` 中审核事实。仅 biological_parent/biological_grandparent 参与祖先计算；名义、收养、误认、婚姻、恋爱与师承分开返回。返回共同祖先的路径证据、不同生父核验及冲突，不自动编造堂表亲或年龄称谓。没有完整证据不代表没有远亲。工具为只读，沿用会话隔离与DAG读锁。

重新部署空数据卷无需模型重新构图，示例及其构图数据源直接包含修订3。已有数据卷仍不会自动覆盖用户修改：升级前备份并核验旧图SHA256为 `f909d76443f3fb7b6983f2a538acb8d5c1b23ed7aa510eb01e38f419df7c9b24`，只有匹配该已发布版本才迁移；其他版本需逐项合并。旧会话保留原快照，新分析从首页重新使用示例图。不要对新版重复运行 `scripts/correct_novel_kinship.py`，该维护脚本仅接受修订2输入并拒绝未知版本。


亲缘工具会按父系/母系路径直接区分祖父母与外祖父母；缺失父母记录不代表不存在亲缘。运行时只在本轮成功核验亲缘后附加回答检查，防止把不同生父推成完全没有血缘、把师父的子女当作同门、把表亲擅定长幼；新问题和其他数据集不会继承这份本轮检查。

可视化结果仍完整保存在服务端及前端图面板；发送给模型的大段画布结果被替换为包含节点/边数和截断状态的简短回执。亲缘、边属性与算法查询的证据不受这项处理影响。复现的溢出会话从约234,000消息tokens降至44,197（另计工具定义和输出保留），无需增大300k配置。

回答直接使用模型原生流式输出，不再缓存完整草稿或追加第二次模型校对。文学、金融和化学示例统一按此执行，继续沿用当前界面语言、首句结论和末段总结。用量仅累计实际执行的模型请求；中途失败或取消时保留原有失败／取消状态，不将部分正文视为成功完成。

社区与亲缘回答继续使用本轮工具证据和原有提示约束，不额外调用模型重写正文。无参数工具调用的空字符串按空参数对象处理，避免成功工具结果被误判成历史孤立结果。

## 化学分子性质分析

第二个示例随代码包含完整数据和第一张 BO-01 分子预存图（22 个原子、24 条无向化学键，48 条双向存储边），启动安装到服务器数据集目录。首页选择“化学分子性质分析”即可创建独立项目并分析。原始五份 CSV、八张分子图、当前四问 workflow、历史六问资料和来源署名均存于 graph_engine/resources/borylation/。只加载 BO-01，其余七张图仅作为原始资料归档，不作为活动图或额外数据集载入。实验和产物记录保存在图元数据中。主交互示例为 BO-01：22 个重原子、24 条化学键、96 条条件记录。

当前四问依次为溶解性与毒性、环结构、标注硼化候选、合并对称等价位点，使用 properties、rings、structure、symmetry。原 products、conditions、plan 仍支持自由追问。LLM 通过工具读取当前会话中的分子图。四问及标题、界面文本支持中英文；聊天发送框沿用 Tab 连续填入下一题。右侧仅展示真实分子结构，点击原子查看信息，分析高亮按节点 ID 映射到化学结构。

配套 background.md 仅在服务器预置图身份与 SHA-256 匹配时注入本轮背景，不影响金融或小说会话。模型仍需调用 borylation_case_analysis 核对。此例复盘公开实验数据；原作者 GNN 未运行，产物与条件没有逐条对应关系，单硼化转化率不能写成位点选择性。

新部署：按原 Compose 说明配置模型连接并构建启动即可，图加载不需要模型服务。升级：重建 backend、graph-engine-api、graph-engine-worker、graph-engine-mcp、agent-runtime 和 frontend，保留原数据卷；后端服务启动后重建/重启 frontend 以刷新 Nginx 地址。不要替换服务器私有 .env。

化学回答根据本轮成功工具返回的结构、对称分组、条件统计和计划直接流式生成。环归属继续从保存的化学键计算，保留原有证据读取与工具结果。

已核验为硼化示例的会话，每轮工具可用时先强制进行一次当前图证据读取，再允许模型回答，防止相邻条件问题复用历史后跳过核对。读取失败不会循环强制重试；切换数据集、严格格式或无工具调用预算时遵循原流程。

## 金融风控与原始构图示例

“金融股权穿透分析”使用用户保存的三表 PK/FK 图快照（19,436 个节点、26,872 条边），原始持股行仍是节点。金融工具从原始表字段投影出 6,000 个主体、13,436 条股权事实，不以 FK 边方向推断持股方向。首页配套四个授信前核查问题，支持中英文和 Tab 逐题填入。旧金融股权示例仍保留。

`graph_engine/resources/finance_risk/` 保存图、哈希清单和背景。“创建你的图”默认提供独立个人副本：
- 金融风控（CSV 原始三表）：原始文件保存在多表容器中，配置与已保存图一致；初始未构图，用户自行构图并保存。
- StackExchange（SQL 原始数据）：完整原始 SQL，初始未构图。
- arxiv（PT 图）：原始 PT 文件，169,343 个节点、2,315,598 条存储边、128 维节点特征，可直接开始分析。

`graph_engine/resources/example_inputs/manifest.json` 记录完整文件及分片的 SHA-256。为避免 Git 单文件大小限制，按不超过 48 MiB 原始块独立 gzip 压缩；服务流式还原，完整哈希一致后原子发布，无需外部服务器、数据下载或模型构图。修改或删除个人副本后不会被覆盖、复活。CSV 三张原表的独立哈希也在清单中。

arxiv.pt 保留原始字节。其可选 torch_sparse 缓存不参与读图；缺少该编译扩展时，仅反序列化缓存占位对象，仍要求明确的 edge_index，保留特征、论文文本、标签和掩码。label_texts 作为类别名称读取；不从不透明稀疏对象推测结构。

更新部署时重建 backend、agent-runtime、graph-engine-api、graph-engine-worker、graph-engine-mcp、frontend，保留数据卷。初次安装 arxiv 占约 557 MB 原始文件空间；每用户独立副本和会话快照另占空间。镜像包含约 229 MB 压缩源数据。

金融回答根据本轮工具结果直接流式生成，不再追加发布前的模型校对；统计范围、覆盖缺口、控制树边和累计经济权益仍由原有金融工具计算。本例仅支持授信前股权关联核查。

内置 arxiv 只有原始文件大小、SHA-256 与随代码清单完全一致，且已知节点/边数低于当前大图阈值时，才使用现有可取消加载流程。修改后的副本、其他大型二进制和 append 请求仍受原有阈值约束。


### 分子图的数据源入口

个人数据源列表首次读取时会自动登记已安装的 `borylation-story.npz`，在“创建你的图”→“我的构图数据源”中显示“化学分子性质分析”。点击“查看构图”可独立打开与图工作台相同的 BO-01 分子结构画布，支持缩放、原子选择和候选位点检查，不创建会话、不调用 LLM。分子页面仅展示分子结构，不展示记录关系图或通用构图编辑表单。点击“开始分析”直接选中这张已构好的 BO-01 图，无需重新上传或构图。登记引用服务器预存图，保留来源版本、方向和配套背景身份；不会把实验记录转换成另一张活动图。

首页“使用示例图”与数据源入口都使用统一的四个问题按钮：“属性判断”“环系分析”“位点识别”“对称等价”。点击按钮填入完整问题，圆圈问号展示问题全文；英文界面显示对应英文。重复访问不会重复登记，用户改名会保留，主动删除个人入口后不会自动重建，也不会删除共享示例文件。
