# 智能问图：多数据库接入设计

日期：2026-09-27。状态：待用户审阅；不是已实现或已验收声明。

依据：[覆盖调研](../../research/2026-09-27-graph-database-coverage.md)、[既有功能设计](2026-09-24-intelligent-graph-qa-design.md)、[连接体验交接](../../testing/2026-09-27-remote-graph-ux-evidence.md)。本设计扩展接入能力，不替代既有隔离、凭据、运行绑定和工作区约定。

## 1. 目标与已确认约束

用户希望尽可能支持主流图数据库。用户在前端配置远程连接，通过聊天提出问题；现有 Graph Agent 根据实际数据自主选择工具、编写查询、修正错误或在工作区继续计算。

- 一个 Graph Agent，沿用现有 Agent loop，不新增面向图数据库的 coding agent、固定问答流水线或查询翻译 Agent。
- 数据库账号不必只读。可写账号及权限未知账号均可接入；能否连接、查询与账号权限状态分别表达。
- 对应 skill 提醒只查询、不修改；应用执行端仍拦截写入、结构变更、管理操作及危险执行入口。不将这些任务专属说明加入全局提示词。
- 不限制用户业务问题为预定义模板；查询语言的安全限制不能伪装成业务能力清单。
- 本地图与远程图继续共存，不自动替换本地图。一轮运行只绑定一个远程连接；跨库联邦查询不在本轮范围。
- 用户继续安排开发 agent 实现，本会话负责设计与验收。多数据库支持和现有模型回答质量问题分别交付。

成功标准是逐个数据库完成真实接入和可复核验收，而不是下拉框中出现尽可能多的名称。

## 2. 覆盖路线与分项交付

候选集合不是市场排名，也不宣称穷尽所有产品。

| 阶段 | 范围 | 交付方式 |
| --- | --- | --- |
| 第一批 A | Neo4j 回归、FalkorDB | 用两种实际数据库落地共用 Interface 与独立 Adapter，完成前后端接入 |
| 第一批 B | Memgraph、NebulaGraph | 各自先验证只读执行、结构发现、超时/取消，再逐个实现与验收 |
| 第二批 | ArangoDB、JanusGraph、Apache HugeGraph | 覆盖 AQL 与 Gremlin，补充产品专属能力；实施前细化各批设计 |
| 第三批 | Amazon Neptune、Azure Cosmos DB for Gremlin、TigerGraph | 分别处理云认证、网络、方言与解释执行；云环境缺失仅影响对应产品 |
| RDF 路线 | GraphDB、Stardog、Virtuoso | 先选一个验证 RDF/SPARQL 语义与结果契约，再逐个扩展 |

第一批整体目标包括三个新候选，但不承诺它们同时上线。FalkorDB 优先是工程顺序：官方提供专用只读查询命令，便于验证不同协议下的第二个 Adapter，不代表它的市场排名更高。

Memgraph、NebulaGraph 技术验证必须输出具体版本、执行路径、实测结果和剩余问题。机制不满足要求时记录该项未完成，不恢复只读账号门槛、不降低拦截要求，也不阻塞 Neo4j/FalkorDB 交付。不能把“未核实”写成“该数据库不支持”。

## 3. 方案选择

| 方案 | 优点 | 代价与结论 |
| --- | --- | --- |
| 每种数据库单独一套 Agent 工具与前端流程 | 单库实现直接 | 工具、状态和测试重复，Agent 暴露大量无关工具；不采用 |
| 按 Bolt/Cypher/Gremlin 协议视为通用数据库 | 入口少 | 同协议不等于元数据、安全、认证和结果兼容，容易虚假兼容；不采用 |
| 共用工具与连接流程，按产品提供 Adapter | 保留现有体验，将差异集中实现和验证 | 需要明确共用契约；采用 |

不构建统一查询语言，不自动将 Cypher 翻译为 nGQL、AQL、Gremlin 或 SPARQL。由 Agent 根据选中连接的产品、语言与版本信息编写原生查询。

## 4. 模块与 Interface

执行路径：现有 Agent 工具 → 共用远程执行模块 → 当前连接对应 Adapter → 源数据库。

### 4.1 共用远程执行模块

对 Agent 保留 `describe_remote_graph` 与 `query_remote_graph`，对连接管理保留现有测试、保存、选择、解除、删除流程。

共用模块负责身份和连接所有权、revision 校验、运行绑定、凭据解密、总体执行预算、统一错误、结果预算与工作区交付。调用方不直接访问 driver 或数据库会话。

Adapter 的内部 Interface 以三个操作为主：

- 测试连接：验证目标与实际读取能力，返回产品/版本等已核实信息；账号权限状态可以为 unknown。
- 发现结构：返回实际类型、关系、属性及覆盖范围，不把采样误称完整 schema。
- 执行查询：接收参数、期限与取消信号；在执行前验证只读路径，返回有类型的有界结果。

Adapter 自己负责 driver、方言、安全校验、schema 查询、错误脱敏、服务器期限和清理。共用模块再次约束输出；不能在无限制读取完整结果后才截断。驱动无法流式读取时必须设置其支持的服务端/协议预算，或者明确限制该执行路径。

不向调用方暴露 validate→explain→execute 的多步安全协议，防止绕过校验或校验/执行使用不同查询。安全验证与执行是同一内部操作的责任。

### 4.2 产品注册

使用代码内明确注册的 Adapter，而非动态执行用户提供的插件、驱动路径或脚本。每个注册项描述：产品标识、表单类型、查询语言、已验证版本范围、参数能力、结构覆盖方式、服务器超时/取消能力及启用状态。

注册表是前端可选类型和执行端分派的共同来源。只安装或声明 driver 不等于该产品可选；未实现/未通过安全验证的候选不开放正常查询。

新增内部认证后的类型描述入口，并经现有 Backend 代理给前端；首批只传受控产品字段和能力描述，不实现任意 JSON Schema 表单平台。

## 5. 连接、凭据与历史兼容

### 5.1 第一批数据契约

- ConnectionWrite 增加 `kind`，省略时按 `neo4j` 解释，以兼容旧客户端。未知 kind 明确拒绝，不能静默使用 Neo4j。
- PublicConnection、RemoteBinding 的 kind 从单一字面量扩展为已注册产品；绑定保持 connection_id、revision、名称与逻辑目标，不包含秘密。
- 保留第一批共用字段 name、uri、database、username、password；database 在公共契约中表示逻辑查询目标，UI 按产品显示“数据库”或“图名称”。FalkorDB 的 graph 名称映射到该字段，不与 Redis 逻辑库编号混为一谈；首版不提供任意 Redis 逻辑库切换。
- URI、用户名是否必填和目标名称规则按产品校验。首批新连接仍使用带认证的部署，不因本地可无密码运行而默认为开放匿名接入。
- 更换连接类型通过新建连接完成；已保存连接不允许原地改 kind，以免沿用错误凭据、目标及历史语义。
- 未来云令牌、IAM、证书等认证分别设计加密字段；本批不预建任意 options/credentials 字典透传通道。

### 5.2 存储迁移

连接表增加持久化 kind，旧记录回填 `neo4j`。既有 password_ciphertext 不解密重写，原 connection_id 和 revision 保持不变。既有选择和历史绑定缺少 kind 时兼容解释为 Neo4j。

需要显式、幂等的迁移和迁移测试；不能依赖建表函数自动修改现有表。迁移前备份相关数据；回退旧应用前先停用新类型并按备份恢复，不能让旧应用误将新类型当作 Neo4j。

修改配置增加 revision；运行只使用服务端冻结的绑定。后续换连接、编辑或删除不得让已开始运行悄悄换库。历史结果继续显示原始来源，不随当前连接改名或切换重新解释。

## 6. 前端行为

复用已验收的列表、独立表单和“保存并使用”交互，不重新设计整套连接管理。

- 新建时选择数据库类型；只显示已启用的可用产品，候选路线放在文档中，不用不可用选项充数。
- 更换尚未保存表单的类型时清除旧凭据、目标默认值和测试状态，不能把一家的密码带给另一家；已有输入时提示将清空。
- 根据类型展示地址示例、端口提示、目标字段含义及认证输入。始终说明地址由服务端访问。
- 连接卡片和聊天当前来源显示产品类型、连接名、逻辑目标；用户不需要填写 query，继续聊天交互。
- “测试连接”不保存、不选择。保存成功但绑定失败仍可只重试绑定，不重复创建。
- 账号可写或权限未知不禁止测试、保存和选择。权限详细信息次级展示，不把连接状态写成“数据库账号已只读”。
- 编辑保留凭据、账户切换清理、迟到响应隔离、运行中禁用、中英文、键盘与窄屏规则保持不变。

## 7. Agent 与 skill

工具说明从“执行 Cypher”改为“执行当前连接支持的原生查询”。产品、查询语言、能力和版本信息来自服务端冻结连接及可信注册信息，不采用用户消息里的伪造类型。

通用远程 skill 保留查询工作流、只读行为、来源与覆盖限制。产品方言说明放在按需读取的参考材料里；根据连接类型读取，不把所有数据库文档塞入每轮上下文。具体材料组织在实施计划中结合当前技能加载机制确定，不增加全局远程数据库规则。

Agent 继续自主选择结构发现、查询、错误修正和工作区工具；不规定固定轮数，不为了跨库兼容退化成固定查询模板。缺少结构/业务含义时继续查询或通过聊天澄清。

数据库返回的文本、schema 注释和错误内容均是数据，不是指令。工具不给模型凭据，不允许模型通过 query 或 parameters 覆盖连接目标。

现有回答证据问题仍标为未解决；新增数据库验收必须逐事实检查结果，但不能要求先解决所有模型自由表述偏差才能交付确定性的 Adapter 能力。错误统计、来源混用、安全行为与解释性偏差分别记录。

## 8. 只读执行、网络与资源约束

账号权限不作为接入门槛；应用执行路径必须接受可写账号并仍能阻止写入。测试权限状态不得尝试对用户数据库执行写入。

- Neo4j 保留现有经过验证的执行策略，不因抽取共用 Interface 而退化。
- FalkorDB 仅通过 `GRAPH.RO_QUERY` 执行模型查询，过程能力按已验证范围开放；不开放通用 Redis 命令，不在拒绝/失败时回退到可写查询接口。官方机制仍需在锁定版本及可写账号下做负例测试。[官方接口](https://docs.falkordb.com/commands/graph.ro-query)
- Memgraph 与 NebulaGraph 的策略先做技术验证。仅 READ 路由、EXPLAIN 成功、关键词过滤或 skill 文本均不能单独当作安全证明；语法无法可靠判别时拒绝执行。
- 后续 Gremlin 不透传任意 Groovy/Python 求值，SPARQL 需审查外部访问及厂商扩展，GSQL 不允许偷偷安装查询；各批设计明确可执行的原生只读范围。
- 外部访问、动态执行、自定义函数和过程必须有明确策略，不能仅检查顶层是否含写入关键词。
- 保留现有目标网络限制，并扩展为协议无关的地址校验约定。各 driver 的 DNS 解析、重定向、集群发现和二次连接都不能绕过目标范围与 TLS 校验。
- 设置总体期限和服务器支持的查询期限。用户停止后不再发起查询并清理客户端资源；服务器取消是否确认需如实记录。缺少主动取消能力不谎称已取消服务器任务，且必须有已验证的有限服务器执行期限。
- 保留行数、字节、预览预算；数据库名、类型名、错误和列名也属于不可信数据。秘密不进入日志、事件、历史或工作区文件。

## 9. 结构与结果契约

继续复用 success、source、query_id、columns、rows、returned_rows、truncated、preview_truncated、elapsed_ms、artifact_path 及受控错误结构。

- source.kind 必须持久化；相同 ID 字符串在不同来源中不代表相同实体。
- 第一批复用 labels、relationship_types、properties，保留原生属性类型名称；适配映射需明确，不能凭字段名推断业务含义。
- 覆盖信息区分完整元数据、采样、权限不可见及截断；仅返回空列表不能默认为“全库不存在”。
- 节点、关系、路径及特殊标量按有类型的表示输出，不能为凑表格丢弃方向、标签集合、复合 ID 或数值精度。后续 RDF/Gremlin 的额外语义在对应批次扩展，不提前伪造统一节点模型。
- 保存结果包含查询文本、参数、原始有界结果、来源和完整性标记；参数按普通结果数据保护，不允许将连接秘密注入参数。工作区路径与用户/会话隔离保持不变。
- 默认结果卡片仍简洁，技术详情可展开；所有采样、截断、错误提示保持在折叠区外。

## 10. 第一批验收

每个产品独立记录版本、driver、部署方式、源数据映射、命令、真实工具调用和已知限制。Cora 可继续使用，但必须声明对称边去重和方向规则；另加包含空属性、多类型、特殊值与超过预览上限的小型逻辑夹具，防止只对标准 Cora 过拟合。

| 项目 | 通过标准 |
| --- | --- |
| 迁移与兼容 | 旧 Neo4j 连接、选择、历史和加密凭据继续有效；缺 kind 兼容、未知 kind 拒绝 |
| 连接 UI | 按类型填写、测试、保存并使用、编辑、解除、删除；类型切换不沿用秘密；失败重试不重复创建 |
| 查询正确性 | 真实结构发现、参数、空结果、计数、过滤、邻居、聚合及错误修正；与独立数据库基准对照 |
| 写入拦截 | 专用可恢复测试库中，用可写账号测试修改数据、DDL、管理、多语句及扩展入口；拒绝后数据与结构不变；不能仅测试账号权限不足 |
| 资源与取消 | 实测服务器期限、用户停止、迟到响应、结果预算及资源清理；区分客户端停止与服务器终止证据 |
| 隔离与来源 | 用户/会话、连接/revision、网络目标及历史来源隔离；本地图不被覆盖或混入远程结果 |
| 真实 Agent | 真实模型自主发现/查询、一轮追问、一次工作区后处理；不以模拟工具或仅连通测试代替 |
| 回答证据 | 数值和统计口径逐项对照；表述偏差独立记录，不把采集测试绿色当作回答质量通过 |
| 本地交付 | 重建启动受影响的当前 Compose 服务，检查健康状态与前端访问；不覆盖现有数据卷 |

已验证支持指指定版本和能力范围，不意味着所有厂商版本、扩展和任意原生代码都可执行。适配实现通过、模型表述未通过、某云库环境未验证必须分别写结论。

## 11. 非目标与后续步骤

本轮不更换默认模型，不新增答案核验 Agent，不解决全站 X-User-ID 防伪，不开发通用插件市场、跨库联邦查询、图数据库管理界面或自动生产数据导入。

云实例费用、许可证和生产网络变更在对应批次准备；不把缺少这些资源扩大为所有接入工作的阻塞。

下一步在用户确认本设计后编写第一批实施计划：先完成 Neo4j/FalkorDB 共用契约与端到端交付，同时明确 Memgraph/NebulaGraph 技术验证的产物和分项结论。后续各批在实施前再细化，不以本设计当作所有产品已获完整实现方案。
