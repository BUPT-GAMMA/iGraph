# iGraph Agent 系统功能检查单

> 检查基线：当前工作区代码及 `igraph-front` 服务器部署，2026-09-04
> 文档性质：静态代码审查 + 可执行验收清单 + 本轮运行时执行记录；`[x]` 表示本轮已按条目核心路径实测，`[ ]` 表示尚未完整覆盖。
> 实现判定：✅ 已有完整代码路径或本轮通过；🟡 部分支持、部分覆盖或依赖配置；❌ 当前未实现/不满足目标。
> 详细实测证据：[AGENT_SYSTEM_FUNCTION_TEST_REPORT_2026-09-04.md](./AGENT_SYSTEM_FUNCTION_TEST_REPORT_2026-09-04.md)

## 1. 总体结论

| 能力 | 代码判定 | 结论 |
| --- | --- | --- |
| Agent 多轮流式对话 | ✅ | 后端以后台 Run 启动，前端消费 SSE 事件并维护消息与工具调用状态。 |
| 网络断开后的输出续传 | ✅ | Run ID、事件游标、SessionStorage、恢复接口和指数退避重连均已实现。 |
| 页面刷新后的会话恢复 | ✅ | 可恢复消息、活动 Run、待审批工具调用及事件游标。 |
| 用户主动暂停接收后恢复 | ✅ | 已实现并实测“暂停观看”：断开本页 SSE、持久化 Run ID/事件游标，后台 Run 继续；恢复时追平同一 Run，若暂停期间已完成则以权威会话状态收敛。尚未实现“停止生成”或服务端“暂停执行”。 |
| HITL 暂停与继续 | ✅ | `clear_graph` 会触发工具确认；接受/拒绝后可继续原 Run，并处理重复或过期反馈。 |
| Agent Runtime 重启后恢复 | 🟡 | 已落库的消息和事件可恢复；正在执行的单次模型调用不能从某个 token 精确续跑，进行中的工具调用也不保证自动重做。 |
| 图机器学习异步训练与进度 | ✅ | 训练可作为后台 Job 运行，并通过 `get_job_status` 获取进度和结果。 |
| 浏览器断开但图引擎仍运行 | 🟡 | Job 会继续，Agent Run 也按后台模式运行；需要端到端故障注入验证断线期间事件能否完整追平。 |
| 图训练取消 | 🟡 | 存在 `cancel_job`，但训练在 `asyncio.to_thread` 中执行，取消外层 Task 不保证立即停止工作线程/GPU 计算。 |
| 图引擎重启后的训练恢复 | ❌ | Job 只保存在内存；重启后状态变为 `unavailable`，没有从 epoch、优化器状态或 checkpoint 继续训练的入口。 |
| 已完成模型与图状态持久化 | 🟡 | 完成后的模型产物和图快照可落盘；图分类运行时数据包仍需重载。 |
| 生产级身份认证和密钥保护 | ❌ | 后端主要信任 `X-User-ID`，CORS 为 `*`，自定义模型 API Key 以明文 JSON 保存，不宜直接暴露公网。 |

## 2. 系统功能范围

### 2.1 Web、用户与模型

- ✅ React Web：项目、会话、消息、模型选择、推理强度、规划模式、上传、数据集、图可视化、训练结果卡片。
- ✅ 用户目录：用户启用状态、角色、内置模型白名单及管理员用户管理接口。
- ✅ 模型：内置模型与用户级 OpenAI-compatible 自定义模型增删查。
- 🟡 身份边界：接口可按用户隔离数据，但调用方身份目前仅由请求头声明，不是可信登录态。

### 2.2 Agent Runtime

- ✅ AgentOS 后台 Run、SSE v2 原子事件批次、事件游标恢复。
- ✅ 每用户/会话/Run/Agent 的 Graph MCP 上下文头传递。
- ✅ 工具调用、Reasoning、规划、附件、反馈继续、活动 Run 并发门禁。
- ✅ User Profile、User Memory、Session Context、Decision Log。
- 🟡 Learned Knowledge 依赖 embedding 模型与 API Key；未配置时不会启用。
- ✅ 14 个内置技能，以及用户级候选技能生成、提升、审批、拒绝与加载。
- ✅ Memory CRUD、事件和用量查询，以及 SFT 数据导出。

### 2.3 图数据与分析

- ✅ 上传与导入：文本、边表、三元组、JSON、Excel、PDF、PyTorch/NPZ 图分类数据等代码路径。
- ✅ 图会话、图快照、撤销、版本列表/加载/丢弃、转无向图、清图。
- ✅ 节点/边查询、邻居、搜索、最短路、全最短路、最大流、最小割、生成树。
- ✅ 社区、中心性、连通性、环、拓扑排序、度分析、子图、链路预测、团、可达性、全局指标。
- ✅ 数据集保存/加载、文档上传与检索上下文、子图可视化。
- 🟡 NebulaGraph 能力依赖外部 Nebula 服务及配置。

### 2.4 图机器学习

- ✅ 节点分类：GCN、GAT、GraphSAGE。
- ✅ 链路预测：GCN、GAT、GraphSAGE。
- ✅ 图分类：GCN、GAT、GraphSAGE；包含 HIV ROC-AUC、PCBA macro AP 等数据集指标适配。
- ✅ 预训练：Node2Vec 与 GNN 自监督代码路径。
- ✅ 模型结构可视化、训练、推理、分析报告、产物保存。
- ✅ 图分类 checkpoint 安全扫描、受限反序列化和模型参数契约检查。
- ❌ 训练请求没有 `resume_from_checkpoint`、`start_epoch`、优化器状态恢复或幂等 Job Key。

## 3. 可执行验收检查单

### 基础功能逐项检查

以下条目覆盖普通用户从进入系统到完成一次图分析的完整基础流程。后面的 A–H 部分继续覆盖系统集成、算法、恢复和故障场景。

#### BF-A. 进入系统与基础界面

- [x] **BF01 有效用户进入系统**（✅）
  - 操作：使用用户目录中已启用的用户 ID 打开系统。
  - 期望：用户校验成功，项目、最近任务、可用模型和个人工作区正常加载。

- [ ] **BF02 无效或停用用户访问**（✅）
  - 操作：分别使用空用户 ID、不存在用户和已停用用户访问页面及 API。
  - 期望：请求被明确拒绝；不会进入空白页，也不会看到其他用户数据。

- [ ] **BF03 默认 General 项目**（✅）
  - 操作：使用第一次进入系统的新用户加载项目列表。
  - 期望：存在默认 General 项目；它不能被删除或改名，可承接未指定项目的会话。

- [ ] **BF04 侧边栏与最近任务**（✅）
  - 操作：展开/收起项目树和侧边栏，打开项目、项目内会话及最近任务。
  - 期望：选中状态、项目归属、会话标题和运行状态标识正确；移动端侧边栏能正常关闭。

- [x] **BF05 深浅主题**（✅）
  - 操作：切换深色/浅色主题并刷新页面。
  - 期望：主题立即切换并通过本地存储保留，主要文字、按钮、弹窗和图区域可读。

- [ ] **BF06 页面刷新与路由恢复**（✅）
  - 操作：分别在首页、项目页、新会话草稿页、已有会话页刷新。
  - 期望：回到对应工作区；不存在重复创建项目或会话；已保存草稿能恢复。

#### BF-B. 项目基础功能

- [x] **BF07 创建项目**（✅）
  - 操作：输入项目名称和可选描述后创建。
  - 期望：项目只创建一次并立即出现在侧边栏；自动打开新项目；名称和描述显示正确。

- [ ] **BF08 创建项目输入校验**（✅）
  - 操作：尝试空名称、纯空格名称，以及超过 80 字符的名称和超过 500 字符的描述。
  - 期望：空名称不能提交；前后端长度约束一致；错误提示清楚，弹窗不会无故关闭。

- [ ] **BF09 编辑项目**（✅）
  - 操作：修改普通项目的名称与描述并保存，再刷新页面。
  - 期望：项目树和项目主页同步更新；刷新后内容仍存在。

- [ ] **BF10 General 项目保护**（✅）
  - 操作：尝试重命名或删除 General 项目。
  - 期望：重命名入口禁用或后端拒绝；删除入口不出现且接口直接拒绝。

- [ ] **BF11 项目主页统计**（✅）
  - 操作：进入项目主页并新增/删除会话和数据集。
  - 期望：Conversations、Datasets 数量及默认数据集标识及时更新，刷新后与服务端一致。

- [ ] **BF12 删除项目并保留会话**（✅）
  - 操作：删除普通项目时选择“移动到 General”。
  - 期望：项目及其项目数据集被删除；全部会话、消息保留并移入 General；会话图运行时按 General 默认数据集重置。

- [ ] **BF13 删除项目及全部会话**（✅）
  - 操作：删除普通项目时选择“删除项目和全部会话”。
  - 期望：二次确认清楚；项目、项目数据集、包含的会话、消息和对应图状态不可再访问；其他项目不受影响。

#### BF-C. 会话与普通对话

- [ ] **BF14 新建任务草稿**（✅）
  - 操作：点击“新建任务”或项目旁的加号，在不同项目间切换后返回。

  - 期望：第一次发送时才创建真实会话；会话标题取消息预览；项目会话数增加一次；不会因双击产生重复会话。

- [x] **BF16 空消息拦截**（✅）
  - 操作：输入空字符串或只有空格后点击发送/按 Enter。

- [x] **BF17 输入快捷键**（✅）
  - 操作：在输入框分别按 Enter 和 Shift+Enter。

- [x] **BF18 无图的正常对话**（✅）

  - 期望：Agent 正常流式回答；不会强制调用图工具，也不会因当前无图直接使对话失败。

  - 期望：错误显示在当前会话，不污染其他会话；会话从失败状态释放，用户可安全重试。

  - 期望：消息、模型、数据集、图、工具卡片和运行状态恢复一致；历史消息不重复。

- [ ] **BF25 删除会话**（✅）

  - 期望：消息保留，两个项目计数更新；会话绑定目标项目默认数据集，旧图运行时被重置，不保留错误的数据集引用。

- [ ] **BF27 选择内置模型**（✅）
  - 操作：在新会话草稿和已有空闲会话中选择不同内置模型并发送消息。
  - 期望：选中的模型被保存并实际用于 Run；用户无权使用的模型不显示且后端拒绝。

- [ ] **BF28 自定义模型基本流程**（✅）

  - 期望：服务端 Job 持续；恢复 Agent Run 后补齐进度/终态，不重复提交第二个训练 Job。

- [ ] **H02 页面刷新，Graph Engine 不重启**（🟡）
  - 操作：训练中刷新页面并重新进入会话。
  - 期望：活动 Agent Run 和工具卡片恢复；同一 `job_id` 继续轮询；最终结果可见。

- [ ] **H03 用户取消训练**（🟡，需重点故障验证）
  - 操作：训练期间调用 `cancel_job`，持续观察 CPU/GPU、产物目录和 Job 状态。
  - 当前风险：取消 asyncio Task 不一定停止 `to_thread` 中的底层训练。
  - 合格标准：训练循环具备协作式 cancellation token；在有限时间内停止计算；状态稳定为 cancelled；不留下可被当成完整模型的半成品。

- [ ] **H04 Graph Engine 优雅重启**（❌，当前预期失败）
  - 操作：训练中重启 Graph Engine 容器，服务恢复后查询原 `job_id`。
  - 当前结果：JobManager 内存表丢失；项目训练卡片只能降级为 `unavailable`。
  - 合格标准：持久化 Job ledger，重启后至少能可靠判定 interrupted；若承诺恢复，则从最近 checkpoint 继续而不是从头训练。

- [ ] **H05 Graph Engine 强制终止/宿主机重启**（❌，当前预期失败）
  - 操作：训练中强制结束容器或重启主机。
  - 合格标准：恢复后能够识别僵尸 running 状态并原子地转为 interrupted/recovering；不得永久卡在 running。

- [ ] **H06 epoch/checkpoint 续训**（❌，当前预期失败）
  - 操作：训练若干 epoch 后中断，使用原 Job 或显式 resume 请求恢复。
  - 当前结果：请求模型无 resume 字段，checkpoint 主要用于完成后的推理；没有 epoch、optimizer、scheduler、随机数状态恢复。
  - 合格标准：周期性原子 checkpoint 至少包含模型、优化器、scheduler、epoch、最佳指标、随机种子/状态、数据与图版本指纹；恢复时校验兼容性并从下一 epoch 继续。

- [ ] **H07 重复提交与幂等**（❌）
  - 操作：网络超时后对相同训练请求重试两次。
  - 合格标准：客户端提供 idempotency key；服务端返回同一 Job 或拒绝重复，不并行消耗两份资源。

- [ ] **H08 断点不兼容保护**（❌）
  - 操作：改变图版本、特征维度、模型配置后尝试从旧 checkpoint 恢复。
  - 合格标准：通过数据指纹、图版本、模型 schema 和代码版本校验拒绝不兼容恢复，并给出清楚原因。

- [ ] **H09 恢复过程可观测性**（❌）
  - 操作：触发中断与恢复，检查日志、状态 API 和 UI。
  - 合格标准：记录原 Job、新执行尝试、checkpoint、恢复次数、恢复起始 epoch 和失败原因；UI 区分 running/recovering/interrupted/unavailable/cancelled。

## 4. 中断恢复能力矩阵

| 场景 | 当前能力 | 数据是否可追平 | 计算是否继续 | 建议优先级 |
| --- | --- | --- | --- | --- |
| 短时网络断开 | ✅ 自动重连 | 是，按事件游标 | 服务端 Run 继续 | 保持并做混沌测试 |
| 页面刷新/切会话 | ✅ 可恢复 | 是 | 后台 Run 继续 | 保持并覆盖 E2E |
| 用户主动暂停观看 | ✅ 已实测 | 是，按 Run ID/事件游标；终态以会话激活接口收敛 | 服务端 Run 继续 | 保持并补刷新/切会话 E2E |
| 用户主动暂停执行 | ❌ | 未定义 | 不能持久暂停模型调用 | P0：先明确产品语义 |
| `clear_graph` 等待审批 | ✅ | 是 | Run 进入 paused | 保持 |
| Agent Runtime 重启 | 🟡 | 已落库事件可恢复 | 单次 LLM/tool 调用不保证 | P1：定义重试边界与幂等 |
| 浏览器断开时训练 | 🟡 | Agent 事件可续传 | Graph Job 通常继续 | P1：E2E 验证 |
| 用户取消训练 | 🟡 | 状态接口存在 | 底层线程可能继续 | P0：协作式取消 |
| Graph Engine 重启时训练 | ❌ | 只能显示 unavailable | 训练丢失 | P0：持久 Job + checkpoint |
| 宿主机重启时训练 | ❌ | 不能可靠重建 | 训练丢失 | P0：持久 Job + 租约/心跳 |
| 已完成模型重启后推理 | 🟡 | 模型产物可持久化 | 不涉及继续训练 | P1：补数据重载流程 |

## 5. 安全与生产就绪检查

- [ ] **S01 真实身份认证**（❌）
  - 当前风险：客户端可声明 `X-User-ID`；若服务直接暴露公网，可能冒充其他用户。
  - 合格标准：由受信网关/JWT/OIDC 建立身份，后端忽略外部伪造用户头，并对管理员接口做角色校验。

- [ ] **S02 CORS 与网络暴露**（❌）
  - 当前风险：Backend 和 Graph 服务允许 `*`。
  - 合格标准：只允许部署站点来源；Graph HTTP/MCP/PostgreSQL 仅内部网络可达；公网只暴露反向代理入口。

- [ ] **S03 自定义模型密钥存储**（❌）
  - 当前风险：API Key 以明文 JSON 持久化。
  - 合格标准：使用密钥管理服务或至少主密钥加密；日志、响应、导出与备份均不含明文；支持轮换和删除。

- [ ] **S04 文件上传与安全反序列化**（✅/🟡）
  - 操作：路径穿越、超大文件、伪扩展名、恶意 `.pt`、损坏 PDF/Excel。
  - 期望：路径被限制在用户目录；大小/类型受控；图分类 checkpoint 的 unsafe global 检查生效；进程不崩溃。

- [ ] **S05 破坏性操作策略**（🟡）
  - 当前实现：`clear_graph` 需要 HITL，训练请求视为用户已授权。
  - 验收：逐项审查删除项目/会话/数据集、覆盖图版本、取消 Job 是否需要二次确认、审计日志或软删除。

- [ ] **S06 限流和资源隔离**（🟡）
  - 操作：单用户与多用户并发提交大图算法和训练。
  - 期望：用户级/全局并发限制有效；请求排队或被清楚拒绝；不会饿死普通健康与状态查询。

## 6. 当前缺口的实施验收标准

### P0-1 Agent 暂停/恢复

- 明确区分“暂停观看”“停止生成”“暂停执行”三种语义。
- Composer 增加独立 `onPause/onResume/onStop`，不能复用 `onSend`。
- 状态机至少覆盖 `running → pausing/paused → reconnecting/running → completed/failed/cancelled`。
- 暂停/恢复请求幂等；刷新或换设备后仍能看见真实服务端状态。
- 恢复以 Run ID + 原子事件游标为边界；工具副作用最多执行一次。

2026-09-04 进度：已完成并实测“暂停观看/继续接收”以及暂停期间 Run 已结束的权威终态收敛；“停止生成”和服务端“暂停执行”仍未实现，刷新/切会话专项 E2E 尚待补齐。

### P0-2 图训练持久化与断点恢复

- Job 元数据写入持久数据库：所有者、会话、请求指纹、状态、尝试次数、心跳、checkpoint、错误和时间戳。
- worker 通过租约/心跳认领 Job；启动时扫描过期 running Job 并转入 recovering/interrupted。
- 每 N 个 epoch 或 N 分钟原子写 checkpoint，并保留最近有效点。
- checkpoint 保存模型、优化器、scheduler、epoch、最佳指标、RNG、数据/图版本指纹。
- 训练循环检查 cancellation token；取消后清理或标记不完整产物。
- 重试使用 idempotency key，避免重复训练与重复产物。
- UI 明确展示 interrupted、recovering、resumed-from-epoch、cancelled 和 unavailable。

### P0-3 公网部署安全

- 在公网入口启用 HTTPS 与可信认证；Backend 不信任用户可控身份头。
- 限制 CORS 和各容器端口；数据库、Graph HTTP/MCP 仅内部可访问。
- API Key 加密存储并从日志/导出中脱敏。
