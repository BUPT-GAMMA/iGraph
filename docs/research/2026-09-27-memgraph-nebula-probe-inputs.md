## 原生接口与安全判定

**Memgraph。** 官方 Python 接入支持 Neo4j Bolt driver，参数仍应通过 driver 的参数映射传入，不能插值拼接；用 `RETURN $x AS x`、`MATCH (n:Probe {id:$id}) RETURN n` 验证字符串、数字、列表及恶意引号按值传递。[官方 Python 接入](https://memgraph.com/docs/client-libraries/python)、[Neo4j Python 参数 API](https://neo4j.com/docs/python-manual/current/query-simple/)。结构发现候选为 `SHOW NODE_LABELS INFO`、`SHOW EDGE_TYPES INFO`、`CALL schema.node_type_properties() YIELD ...`、`CALL schema.rel_type_properties() YIELD ...`、`SHOW INDEX INFO`；这些是 Memgraph 原生命令/模块，逐项在锁定版本和无 MAGE 镜像上验证字段及空图行为。[官方 schema 说明](https://memgraph.com/blog/using-schema-functions-to-model-your-data-in-memgraph)、[发行记录](https://memgraph.com/docs/release-notes)。

Neo4j Python `READ_ACCESS` / `execute_read` 主要是路由提示，官方明说不能依赖它拦截写入。Memgraph v3.13.1 源码确有内部 `ReadWriteTypeChecker`，分 `NONE/R/W/RW`；`CALL` 按过程声明的 `GraphAccess::Write` 归为写，否则归为读；解释器把分类写入执行摘要 `type`。这证明内部存在分类，**尚不证明**有执行前、覆盖所有语句并可供客户端调用的拒绝接口，更不能把 Neo4j 的 `summary.query_type` 语义直接套上。`EXPLAIN` 返回 Memgraph 算子文本，`PROFILE` 会执行查询，均不能未经负例验证充当安全闸。`CALL` 可触发写过程、模块文件修改或外部 I/O；即使过程注册为 read procedure，也只说明图数据写权限，不能推出无文件/网络副作用。[Neo4j 驱动说明](https://neo4j.com/docs/python-manual/current/transactions/)、[Memgraph 分类源码](https://github.com/memgraph/memgraph/blob/v3.13.1/src/query/plan/read_write_type_checker.cpp)、[解释器摘要源码](https://github.com/memgraph/memgraph/blob/v3.13.1/src/query/interpreter.cpp)、[Memgraph EXPLAIN/PROFILE](https://memgraph.com/blog/how-to-read-query-execution-plans-optimize-queries)、[内置模块文件操作](https://memgraph.com/docs/release-notes)、[官方 read_proc 网络/文件示例](https://memgraph.com/blog/how-to-implement-custom-json-utility-procedures-with-memgraph-mage-and-python/)。下一步核对该内部分类能否形成可验证的执行前策略，并用可写账号实测；未知语法/过程拒绝。缺少机制是**未解决**，不等于证明产品不支持。

**NebulaGraph。** 使用官方 `nebula3-python` 的 `ConnectionPool` / `session_context` 或单 user + 单 space 的 `SessionPool`；README 明确后者固定 user/space，并警告别在池中执行改密码或删用户操作。参数 API `execute_py(query, params)` 示例用 `$p1`、`$ids`，但文档说明不能参数化所有 token，Console 特别写明 VID 位置和 `SAMPLE` 不支持；逐项实测，不拼接标识符。[官方客户端 README](https://github.com/vesoft-inc/nebula-python)、[Console 参数限制](https://docs.nebula-graph.io/3.8.0/nebula-console/)。结构以 `SHOW TAGS` / `DESCRIBE TAG`、`SHOW EDGES` / `DESCRIBE EDGE`、必要时 `SHOW TAG/EDGE INDEXES` 为准；`SHOW STATS` 需先跑有副作用的 `SUBMIT JOB STATS`，不得在模型只读路径自动发起。[nGQL 速查](https://docs.nebula-graph.io/3.8.0/2.quick-start/6.cheatsheet-for-ngql/)、[Job 语句](https://docs.nebula-graph.io/3.8.0/3.ngql-guide/4.job-statements/)。

nGQL 包含原生命令、Cypher 风格语法和复合语句；Studio 官方说明可用分号执行多语句，故只看首词不够。`EXPLAIN` 可给计划且不执行，`PROFILE` 会执行；没有官方证据说明 EXPLAIN 结果就是完整安全分类。3.8 源码的 `PermissionCheck` 按 `Sentence::Kind` 分数据写、schema 写、用户写、job 等并做角色检查，且 `enable_authorize=false` 时直接跳过；这表明存在服务端角色约束，但未找到可直接给可写客户端调用的“分类但不执行”API。3.8 文档说 `CALL[…YIELD]` 尚不支持，但仍须测试拒绝所有可触发作业/管理动作的路径，不可仅因 `CALL` 不支持就跳过副作用探针。[多语句](https://docs.nebula-graph.io/3.8.0/nebula-studio/quick-start/st-ug-console/)、[EXPLAIN / PROFILE](https://docs.nebula-graph.io/3.8.0/3.ngql-guide/17.query-tuning-statements/1.explain-and-profile/)、[权限源码](https://github.com/vesoft-inc/nebula/blob/v3.8.0/src/graph/service/PermissionCheck.cpp)、[YIELD 限制](https://docs.nebula-graph.io/3.8.0/3.ngql-guide/8.clauses-and-options/yield/)、[Job 语句](https://docs.nebula-graph.io/3.8.0/3.ngql-guide/4.job-statements/)。服务端授权可作为防御层，但 Task 7 要在专用可恢复库用有写权限的账号证明应用执行路径自身拒绝；不能靠只读角色掩盖分类缺口。[角色与权限](https://docs.nebula-graph.io/3.8.0/7.data-security/1.authentication/3.role-list/)。

## 可重复的 pass/fail 探针

每个产品由管理员**只在隔离实例**准备固定小图、可写账号和唯一 canary ID；负例只交给待测的模型查询执行入口，事前事后用独立管理员连接读取节点数、属性、schema、用户/作业/模块列表。通过条件是入口拒绝且所有快照一致；语法错误、账号无权限或后续回滚都不能单独算“应用拦截通过”。先用管理员直连确认每条负例在该版本和该账号本来可执行，再重置环境。[Task 7 验收范围](../archive/superpowers/plans/2026-09-27-multi-database-graph-qa-phase1.md)、[Memgraph Cypher 示例](https://memgraph.com/docs/client-libraries/python)、[Nebula nGQL 速查](https://docs.nebula-graph.io/3.8.0/2.quick-start/6.cheatsheet-for-ngql/)。

最小夹具：Memgraph 在隔离实例 `CREATE (:Probe {id:'p1'})`；Nebula 先 `CREATE SPACE qa_probe (partition_num=1, replica_factor=1, vid_type=FIXED_STRING(32))`，等待 space 就绪后 `USE qa_probe; CREATE TAG Probe(id string)`，再 `INSERT VERTEX Probe(id) VALUES "p1":("p1")`。Nebula 的 space/tag 名是管理员固定配置，不能由模型拼接。每轮负例后从快照恢复，不复用已污染的夹具。[Memgraph CREATE](https://memgraph.com/docs/querying/clauses/create)、[Nebula CREATE SPACE](https://docs.nebula-graph.io/3.8.0/3.ngql-guide/9.space-statements/1.create-space/)、[Nebula 速查](https://docs.nebula-graph.io/3.8.0/2.quick-start/6.cheatsheet-for-ngql/)。

## 期限、内存和取消

- Memgraph 有服务端 `--query-execution-timeout-sec`、运行时 `query.timeout`、`QUERY MEMORY LIMIT` 和进程 `--memory-limit`；区别记录客户端等待超时与服务端确实停止。`SHOW TRANSACTIONS` / `TERMINATE TRANSACTIONS` 是候选取消路径，3.13.1 修正了权限结果和若干过程响应取消的行为；必须在目标版本以自己的 query ID 验证，不给模型开放管理命令。[官方性能说明](https://memgraph.com/blog/handling-large-graph-datasets)、[发行记录](https://memgraph.com/docs/release-notes)。
- Nebula 3.8 文档列出 `SHOW [LOCAL] QUERIES` 和 `KILL QUERY(SESSION=...,PLAN=...)`；`SHOW QUERIES` 经 Meta 同步有延迟，非 GOD 只能杀自己的查询。graphd 的 `storage_client_timeout_ms` 是到 Storage 的 RPC 等待，不是通用查询截止；配置页给出查询长度和内存追踪参数，但未确认可设置每查询服务端 wall-clock deadline。探针需证明可在有界时间内找到并取消自己的查询，且取消后服务端停止、资源恢复；否则报告为未验证。[SHOW QUERIES](https://docs.nebula-graph.io/3.8.0/3.ngql-guide/7.general-query-statements/6.show/18.show-queries/)、[KILL QUERY](https://docs.nebula-graph.io/3.8.0/3.ngql-guide/17.query-tuning-statements/6.kill-query/)、[graphd 配置](https://docs.nebula-graph.io/3.8.0/5.configurations-and-logs/1.configurations/3.graph-config/)。

**进入产品实现的门槛：** 分别记录精确镜像 digest/客户端版本、管理员直连正控、应用入口负控的状态前后差异、网络可达性、并发隔离、服务端期限/取消证据，以及未覆盖的语法和过程。任何可靠分类或服务端约束缺失时仅记“尚未验证/当前方案不通过”，不得标记已支持；也不由资料缺口推断该产品没有能力。[Task 7](../archive/superpowers/plans/2026-09-27-multi-database-graph-qa-phase1.md)。
