### 保存与准入

原生 phase 写入在调用 Agno 存储前保留待确认副本，内容仍通过原生会话存储保存。异常和存储内部吞掉错误的情况都必须经过读回核对；成功确认账本后清除副本。没有原生结果时，只有确实未进入原生执行的证据允许确认 `native_run_created=false`。

待审批状态已经保存，只能证明暂停阶段可靠保存。点击停止后撤销这项保存确认，取消终态写入成功后才重新确认；审批继续和停止仍使用共同执行边界。

已证明旧执行者退出时，可以从原生检查点保存失败或取消终态，保留已有输入、文本和工具结果。收尾直接更新存储，不重新调用模型或重跑业务。执行证据、结果或身份缺失时保留 pending 和明确错误。

### 服务重启与提交

Runtime、BFF、Graph 服务和独占 worker 使用 UUID 对应的内核文件锁记录寿命。查询不会创建缺失锁文件；缺失、损坏或不可读均为 unknown。worker 在放行业务输入前写入进程组及创建时间，控制管道 EOF 触发专属进程组停止。

Graph 恢复先核实旧服务退出，再校验和回收所属 worker 及后代进程。作业结果先持久保存，随后确认 terminal_persisted。同步数据库线程收到取消后仍由服务持有，真实退出后才释放寿命锁，避免新执行者与旧写入重叠。

图版本使用不可变 NPZ 与原子 manifest；失败提交留下的候选文件保持不可见。图、模型、数据集和文档的正式发布保留归属与代次凭据。恢复同时检查正式文件中的匹配凭据，索引文件本身不会授予成功状态；发布后、作业确认前崩溃仍能恢复已提交结果。

模型在 worker 内完整读回 checkpoint、元数据与数组，遵循各任务现有的安全读取规则。暂存目录与发布目标位于同一文件系统。历史版本操作保留既有响应字段，并从公开版本列表隐藏内部提交凭据。
