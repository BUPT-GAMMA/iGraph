# 智能问图设计草案

状态：开发中；2026-09-26 用户确认以下权限调整，优先于旧版设计和验收记录。

本功能是现有 Agent 的可选能力扩展：前端增加连接配置入口，后端增加必要的连接接口和查询工具，并提供配套 skill。Agent 根据用户任务自主选用这些能力；配置远程连接不强制每轮查询数据库，也不关闭原有图工具或工作区工具。

## 2026-09-27 连接体验与回答证据增量

连接面板默认展示列表和空状态；新建、编辑进入独立表单。主操作“保存并使用”在保存成功后绑定当前会话；保存成功而绑定失败时保留已保存的连接 ID，显示“已保存，未使用”，重试只绑定。独立测试连接既不保存也不选择，编辑配置清除测试状态。列表明确标注会话选择，解除选择保留连接，删除移除用户连接。首期只展示 Neo4j。

地址提示说明服务端连接和 localhost 的环境含义，数据库名和编辑时空密码规则在字段旁说明。沿用项目主题变量、按钮层级、窄屏和键盘操作；账户切换与卸载隔离待完成操作，运行中禁止修改。

结果默认显示来源与有限预览；查询、连接/查询 ID、版本及完整工具预览在技术详情中展开。结构采样、结构/结果截断、预览缩短和工具错误均在折叠区域外显示，包括尚无来源的预检错误。图对象的内部标识保留在详情中。

remote-graph-qa skill 要求回答的每项数据库事实与查询结果或明确可信上下文对应，包括总结。结构名和属性类型不能证明业务含义；需要维度/类别数时自主查询，不需要则省略。Cora 导入的对称边去重约定不能用于推断其他同名连接的来源。规则保留在 skill，工具调用顺序和次数仍由现有 Agent 决定。

真实模型验收重放会话 `ac060ccc-a9a7-4c2b-ab1e-54584f6f2ff7` 的原问题，再查询维度/类别和澄清业务含义。完整回答、工具参数、工具结果与直接 Neo4j 基准一起存档，逐项审阅；测试脚本的绿色状态只是链路证据，不能替代回答事实审查。

## 已确认的需求

- 功能定位：为现有 Graph Agent 增加远程图数据库查询能力，不将产品重新定位为面向图数据库的 coding agent，也不新建独立 Agent 产品。
- 用户提供远程图数据库连接信息，并通过 iGraph Agent 提问。
- Agent 根据用户问题和实际数据自主编写、执行查询。产品不通过预设问题类型或固定查询模板限定其问答能力。
- 智能问图仅提供源数据库查询能力，应用执行端禁止修改源数据库；数据库账号可以具有写权限。
- `cora.pt` 用于导入数据库，构造端到端问图测试样例；仅完成文件问答不能替代远程数据库链路验证。
- 当前阶段讨论需求并沉淀文档，后续再开始功能开发。

## 已确认的方案边界

- 首期选择一种使用广泛的图数据库跑通完整链路，选型优先考虑用户生态，不以复用仓库已有 Nebula 依赖为主要依据。首期使用 Neo4j；本地测试允许 Community。
- Agent 通过工具了解数据库结构并执行自主编写的原生查询，可以利用现有工作区对返回结果继续计算；不采用工作区脚本直接持有凭据连接远程数据库的方案。
- 数据库账号只读不再是接入前提。账号可写或权限元数据不可读，不阻止连接、保存、选择或查询。Cora 导入限于独立可恢复测试实例，可使用该实例的管理账号。
- 只读行为要求仅写在智能问图功能的 skill 中，不加入 Agent 全局上下文，不影响其他任务。该 skill 明确禁止修改源数据库的数据、结构和权限；查询执行端独立拦截写入、结构变更和管理操作。
- 前端增加合适的连接配置入口。连接归当前用户保存，可在本人会话间复用；会话明确选择并显示当前数据源，首期一次围绕一个数据源问答，不做跨库联合查询。数据源有歧义时通过聊天澄清。
- 不额外设置数据含义说明表单。Agent 自动发现数据库结构，业务含义或用户意图不明确时直接通过聊天澄清。
- 首版复用现有聊天和工作区成果展示，支持展开查看执行的查询和结果摘要。图画布联动不作为首版必需能力。
- 查询工具接入现有 Agent loop，由 Agent 自主选择工具、多轮查询并根据错误修正，不逐条请求用户确认，不另建独立 ReAct 循环。

## 连接可用与权限核验

采用独立 Neo4j Community 容器和数据卷进行本地验证；部署、凭据生成和 Cora 导入已获用户授权，由开发者完成。Enterprise 和 reader 角色不是强制前提。

测试连接返回 `connection_usable: true`，表示认证和目标库读取成功。`database_read_only` 单独报告 `verified_read_only`（当前权限元数据明确支持只读结论）、`not_read_only`（检测到写入或管理权限）、`unknown`（不支持、无权读取、超时或信息不足）。后两者均不阻止使用；状态仅代表本次测试，不是永久授权证明。不得将 `RETURN 1`、驱动 `READ_ACCESS` 或应用层只读检查当成数据库账号只读的证据，不在用户库执行写入探针。

查询执行继续采用单条查询限制、执行入口白名单和服务器 EXPLAIN 类型核验；只允许类型 `r` 后执行。数据库端最小权限仍可由部署者配置作为额外防护，但不构成接入门槛。参考：[Neo4j 访问模式](https://neo4j.com/docs/python-manual/current/transactions/)。

现有 Backend 信任 `X-User-ID` 的问题单独记录为未解决的多用户部署限制。保留已有服务认证、会话归属和连接所有权检查；本次不改造整站认证，不宣称身份防伪验收通过，也不因此阻断隔离本地功能验证。

## 方案草案（待整体审阅）

1. 前端连接入口提供连接名称、地址、数据库名、账号及凭据，并支持测试连接、保存、编辑和删除；会话选择当前数据源。
2. 后端按可信用户身份解析连接，凭据不进入模型上下文、工具结果或工作区。会话中的连接引用不构成跨用户授权。
3. 为现有 Agent 增加数据库结构发现与原生查询工具。结构发现提供实际标签、关系类型及属性等信息；查询工具执行模型生成的 Cypher，返回结构化结果、查询依据和执行状态。
4. 查询结果在受限大小内提供模型可读摘要；需要继续计算时可生成当前会话工作区可读的结果文件。明确标注截断或不完整结果，不将其当作全库统计依据。
5. 智能问图 skill 提供按需发现结构、编写查询、核对结果、处理错误及回答问题的指导，并明确只能读取源数据库，禁止修改数据、结构和权限。这些行为要求仅放在该 skill 内，不加入 Agent 全局上下文。它不代替执行工具、不实现另一个 Agent loop，也不规定固定问题类型。
6. 复用现有工具执行展示，呈现查询和结果摘要；最终回答依据实际查询结果，业务语义不明时通过聊天澄清。
7. 查询执行设置可配置的超时、结果行数及字节上限；具体默认值在实现方案中明确。停止操作需区分 Agent 停止后续调用与数据库正在执行的查询是否已取消，不能把客户端超时等同于服务端查询停止。

## 用户流程与连接生命周期

在现有数据源选择区域增加“远程数据库”入口，打开连接配置面板。首期仅展示 Neo4j，填写连接名称、URI、数据库名、用户名和密码，提供独立测试连接与保存并使用操作。无需填写业务描述、查询模板或 skill 配置。

连接可在本人会话间复用。会话显示当前问题所针对的数据源，并可绑定一个供远程工具使用的连接；这是查询目标选择，不是互斥的 Agent 模式。已有上传图和原有工具仍可用，远程查询结果可以继续交给工作区工具处理。保存连接不代表自动导入数据库内容，也不替换原有上传图。只有任务需要远程数据库且缺少连接或指代不清时才澄清；普通聊天和其他任务不因未配置连接而受阻。首期不实现多个远程库的联合查询。

每次 Agent 运行固定远程查询目标和连接配置版本；运行中切换连接或修改配置在下一轮生效。当前运行再次调用远程工具时若发现连接配置已变更或删除，返回连接失效状态，由用户重新发起任务，不在同一运行内静默切换凭据或数据库。已经开始的查询由超时和停止机制控制。已经生成的回答与结果文件保留来源名称、连接版本和查询时间，历史证据不随当前选择改写。

## 工具与执行服务

工具名称为建议命名，最终沿用项目约定：

| 工具 | 模型提供的输入 | 返回内容 |
| --- | --- | --- |
| `describe_remote_graph` | 可选的标签或关系类型过滤条件 | 当前连接标识、数据库类型、标签、关系类型、属性及结构发现的覆盖范围 |
| `query_remote_graph` | 原生 Cypher、参数、是否生成结果文件 | 列和记录、查询编号、耗时、截断状态、错误状态及可选工作区文件引用 |

当前连接由后端根据可信用户、会话与运行状态解析，模型不提供账号、密码或任意连接地址。两个工具复用同一执行服务及权限校验，结构信息来自实际数据库，不硬编码 Cora 的 schema。结构发现允许按需收窄范围，不要求每个问题前完整扫描数据库。

首期执行单条参数化查询，不提供管理账号或任意过程执行的替代通道。执行端拒绝已识别的写入、结构变更和管理操作；应用层通过服务器编译/计划元数据核验读操作类型，不能仅依赖字符串关键字检测。确有必要的结构发现过程由适配层明确支持。

结果使用稳定的 JSON 表示节点、关系、路径和属性，保留标识及方向。工具直接返回有限记录供模型阅读；较大结果可在当前会话工作区生成 JSON 文件供现有计算工具使用。模型摘要和文件都要标注完整性，生成文件不意味着绕过查询结果上限。

建议首期默认单次查询 30 秒，最多 10,000 行或 10 MiB，模型预览最多 100 行或 64 KiB，均由部署配置调整。限制属于执行预算，不定义模型能够回答的问题种类。全库统计优先在数据库聚合，不能用截断样本冒充完整计数。

语法错误和可恢复错误原样以脱敏结构返回，由现有 Agent loop 决定修正；凭据失效或权限不足时提示用户修复连接，不重复尝试写入或切换高权限身份。沿用现有停止通路，并在查询执行层尽力取消事务；数据库事务超时用于约束停止信号未成功传递的情况。

## 凭据与结果归属

连接记录包含所有者、配置版本、数据库定位信息和加密后的凭据；密钥通过服务端部署配置提供，不随记录一起存储。列表和查询工具只暴露是否已配置凭据，不返回密码。日志、错误和执行事件需要脱敏，凭据不进入模型、历史消息或工作区。

连接访问与结果文件访问均复用可信用户和会话归属检查。数据库网络连接由服务端发起，因此地址必须从服务端可达；连接测试负责报告连通性。地址处理限定支持的数据库协议，并复用或补充服务端出站地址策略，不能把该接口变成任意协议代理。

## Skill 的职责与加载

新增独立的远程问图 skill，建议命名 `remote_graph_qa`，与现有面向文档检索的 `graph_rag` 区分。通过现有 skill 机制按需加载，不新增一套 skill 执行器。skill 描述和两个工具的说明指向 get_skill_instructions 加载入口；只读行为内容仍仅保存在 skill 正文中。

skill 包含：适用场景、可用工具、按需发现结构的方法、Cypher 查询与结果核对指导、失败和截断的处理、工作区后处理方式，以及源数据库只能查询不能修改的要求。用户要求修改源数据库时，说明该能力只读，并可提供相关查询结果；禁止尝试改数据、schema 或权限。

skill 中的指导不固定工具调用次数或顺序，也不限制问题类别。查询返回的文本与属性作为数据处理，不将其中的指令当成新的行为要求。业务语义不明确时直接询问用户。

不向 Agent 全局指令加入本功能的只读描述。当前数据源名称、类型等会话事实通过既有会话状态提供；查询工具仍在 skill 未加载或模型偏离指导时独立执行权限限制。

现有全局规则中默认查询本地图、无图时提示上传、涉及路径等问题调用 `visualize_subgraph`，以及总体分析或报告任务调用 `create_analysis_report` 的规则，需要明确其适用的数据源和工具前提。远程数据库已选中时不能因本地图为空要求上传，也不能把远程节点标识直接传给只接受本地图的工具。这里仅修正现有规则的适用范围，不新增本功能的全局行为清单。

现有 `create_analysis_report` 在输入缺少图信息时会自动补入当前会话本地图的信息，不能直接用于远程数据库报告。首期远程分析报告通过现有聊天或工作区产物生成，仅在数据源兼容且不会自动混入其他来源时使用现有报告工具；不为此扩展报告系统。本地图 A 与远程库 B 同时存在时，针对 B 的报告只能使用 B 的查询结果及基于这些结果的计算，不能自动补入 A 的节点数、边数等事实。

## 实现接入点

- `agent_runtime/agno_factory.py`：现有 Agent 的工具注册入口，新增查询工具集合，沿用现有 loop 和 hooks。
- `agent_runtime/skills_runtime.py` 与 `agent_runtime/resources/skills/`：复用已有 skill 加载方式，增加本功能 skill。
- `agent_runtime/instructions.py`：适配已有数据源识别规则，以及可视化、报告工具的数据源前提；不放入智能问图的只读行为描述。
- 连接配置沿用现有按用户归属管理资源的模式，新增独立连接接口与存储，不借用模型提供商记录或内部图存储配置。
- 前端复用现有数据源区域、工具执行展示和工作区成果展示，增加远程连接配置与选择能力。
- `agent_runtime/cancellation_compat.py` 与现有执行控制：复用停止信号，新执行服务负责事务取消和资源清理。

上述为模块职责定位，不要求把连接管理、驱动执行和工具包装全部堆入现有工厂文件。

## Cora 验收草案

- 使用受限加载将 `cora.pt` 装入独立测试数据库，记录节点、关系、文本及标签的实际映射；不虚构字段含义或将无向关系误称为有向引用。
- 用测试账号从前端配置并选中该数据库，经现有 Agent loop 完成结构发现、自然语言查询、连续追问和结果解释。
- 对节点数量、指定节点邻居、标签分布等问题，以直接数据库查询作为正确性对照；查询写法不要求固定。
- 验证结果可用于工作区后续计算，回答可查看查询与结果摘要。
- 验证应用工具拒绝写操作，同时如实记录数据库账号权限是否验证；另验证错误凭据、断连、超时、结果截断与跨用户连接访问得到明确处理。
- 验证智能问图 skill 指导 Agent 拒绝执行源数据库修改请求；该任务的只读行为描述不注入全局上下文，也不限制其他任务原有的操作能力。
- 回归验证：未配置连接时原有任务照常工作；配置连接后普通聊天不强制查库，原有图工具与工作区工具仍可按任务使用；远程路径查询不误调用本地图可视化工具。
- 报告来源回归：会话保留本地图 A，同时绑定远程库 B，两者使用可区分的节点数、边数和属性。要求 Agent 对 B 生成总体分析报告，验证报告及其依据均来自 B，不混入 A 的统计；同时验证原有本地图报告功能仍正常。

验收示例包括“这张图有哪些类型和属性”“指定论文的邻居有哪些”“按标签统计数量”及基于上一轮结果的追问。数值、文本和关系以实际导入映射及直接查询结果为准，不预写模型答案。

导入是测试准备步骤，不注册为 Agent 工具。权限拒绝测试仅在可恢复的专用测试数据库中执行；连接用户真实数据库时不得通过尝试写入来测试权限。

开发完成后按照仓库约定重建并启动受影响的当前 Compose 服务，检查健康状态和本地访问地址，同时给出可直接使用的 Cora 测试连接。仅文档修改无需重建服务。

## 讨论原则

模型自主决定如何解决问题；可执行接口的权限和运行约束需要明确。两者分别讨论，不将运行约束等同于预设问答能力范围。
