## 大图进程回收：已确认独立实现缺陷

普通连续复跑不能稳定复现。固定一个本测试持有的无关进程在 `/proc/<pid>/stat` 打开后、读取前退出，真实 Linux 返回 `ProcessLookupError(errno.ESRCH)`，原回收目标连续三次失败：应回收 1 项，实际 0 项。没有伪造 errno、恢复返回值或放松后代终止断言。

`_verified_group_members` 仅忽略 `FileNotFoundError`，把同样意味着进程已消失的 ESRCH 归入“进程表无法完整检查”，导致安全拒绝、任务没有重新入队。修复应只承认这两类消失状态；权限不足、格式损坏及其它 I/O 错误仍应拒绝回收。

旧全仓运行使用 `--tb=no`，没有保存当次 errno；本次证明的是同一个测试目标及恢复阻断的确定性根因，不能追认旧失败内部必然也是 ESRCH。

最终产品修改只有 `runtime.py` 两处：成员扫描及 pidfd 打开后的身份重读，将 ESRCH 与 ENOENT 同视为已消失。初次观察分支的既有 fallback 已能证明进程组为空，回归原本通过，因此不改；pidfd 打开失败的处理也不改。

- 回归先红：10 个窄场景中 2 failed、8 passed，失败为真实无关进程退出竞态及 pidfd 后身份读取竞态。
- 修复后主代理独立复跑：10 passed、44 deselected，10.12 秒。包含权限不足、未知 I/O、损坏 stat 的安全拒绝及显式故障触发断言。
- 独立审查：代码安全边界、测试及归因文档无 Critical／Important 遗留；独立窄测也通过，不将重复执行相加成不同测试数量。
- 前序模块加完整大图 pipeline：`.venv/bin/python -m pytest -q tests/servers/test_graph_data_app.py tests/servers/test_large_graph_pipeline.py --tb=long`，84 passed、34 warnings，80.62 秒。私有完整日志 `/tmp/igraph-stale-prelude-module-green.log`；已检查退出码、摘要及日志脱敏。包含上述 10 项，不重复累加。
