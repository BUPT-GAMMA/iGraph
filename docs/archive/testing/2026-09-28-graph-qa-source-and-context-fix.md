# 智能问图来源与会话上下文修复复核

基线：`7d34f9d4f442aa1210e7f11c87fc1c8a5543b8f7`。范围仅 Neo4j、FalkorDB；沿用 `qwen3.6-plus`、原生 Agent loop 与前端 HTTP/SSE 接口，不要求数据库账号只读。确定性执行修复与自然语言回答质量分别验收；回答质量尚未整体通过。

## 复现与根因

### 来源混淆

通过 `http://127.0.0.1:21108/api` 新建专用测试用户的会话，选择远程 Cora，另上传本地图 `0 1 / 1 2`，开场要求“把 cora_id 为 0 的节点删除。”

- 首次复现：误用 `subgraph_extraction` 修改本地图。
- 基线五次重复：三次实际修改本地图，另两次误调用 `clear_graph` 并停在审批状态。后两次不视为通过。
- 仅加强 skill description 与正文的第一版仍未解决：模型继续跳过 skill、将业务属性当成本地节点 ID。失败批次单独保留，不覆盖。
- 后续分别尝试请求状态中的来源提示、仅绑定远程库时注入的来源提示，仍发生误修改。最后一版两种数据库各五次，均出现错误来源操作或尝试，不以“提示已注入”代替行为通过。
- 证据：`output/frontend-qa-source-fix-20260928/{baseline,baseline-repeated,candidate-source}/`；同目录 `run_checks.py` 复用已有前端 HTTP/SSE 传输，不直连数据库替代主问答。

### 多轮任务偏离

原失败会话第七轮的用户消息正确，但 system 中的 Learning SessionContext 将上一轮已经拒绝的删除记录为 pending。模型首次推理识别了当前查询问题，在工具返回后又回到删除拒绝。

本地 Agno 的学习任务在主模型回答前启动，并复制当时的消息列表。因此摘要能看到本轮用户删除要求，看不到稍后产生的拒绝回答；下一轮将不完整的摘要注入 system。修复应让学习读取完整回答，而不是关闭历史或单纯强化拒绝提示。

### 测试隔离

`tests/servers/test_nebula_integration.py` 在模块收集时加载项目 `.env`，即使该集成测试未执行，也改变其他测试的功能开关。最小复现为一个单独通过的模型测试，加收集此文件后失败。修复将环境加载移至显式 opt-in 后，并限制在测试自身生命周期内。

同类污染也来自导入旧 gateway、entrypoint、igraph 模块的测试文件。局部隔离这些导入的环境副作用；不通过全局 fixture 强行覆盖产品配置。大图后代回收测试另有固定 3 秒逃逸定时与回收耗时竞争，测试改用回收后显式放行；仍在核查进程枚举的另一项间歇失败，不能宣称全仓通过。

- 暂停与取消不写入新摘要。Agno 2.9 post-hook 吞掉普通异常，因此以窄兼容异常保留原生取消状态和活动 SSE 终态。
- 相关回归由实施侧实跑 87 项通过，独立复核另跑 25 项通过；不相加宣称互不重叠的 112 项。
- 2026-09-28 21:20 重建后的真实前端接口：摘要提取开始后取消，收到 `done`、取消状态落库、控制状态可发送；同会话下一轮重新查询成功。证据 `final-cancel-capture/{cancelled,after-cancel}.json`。此前缺失 `done` 的失败证据保留在 `cancel-capture/`。

### 普通聊天来源保护

- 不新增确认卡片、审批端点或新的 Agent loop。按现有工具读写契约，在缺少用户来源答复时停止本地修改，以普通 assistant 消息询问当前本地图还是远程库。
- 用户实际下一条消息明确回复本地图才授予该轮本地来源许可；支持“本地图”“当前本地图”“我指的是本地图”“我指的是当前本地图”及末尾 `。！`，不接受问句、否定、转折或“继续”。模型参数、历史摘要、工具结果、客户端 metadata 均不能授予。切换远程连接版本、换本地数据集、无效答复、上一轮失败或取消不沿用许可。
- 来源已明确后的旧工具审批行为保持原样；同一轮的原生恢复需匹配服务端保存的来源许可，不扩展到下一轮。
- 保守代价：即使首句明确提到本地图，也可能再询问一次；模型自行询问而未触发服务端来源记录时，也可能再问。许可确认的是“当前本地图”，不是数据库事务或图内容快照。真实 BFF 未提供普通图的 `graph_version`，不能声称检测了同数据集内的所有内容变更。
- 21:29 镜像首次真实接口验证发现：用户回复“本地图”后仍重复澄清，未修改本地图。原因是 AgentOS 后台流先将本轮 RUNNING 占位 run 放入 session，来源 hook 误把它当上一轮；此前前台原生测试未覆盖。失败证据 `chat-source-final/neo4j/local/` 保留，补后台 SSE 与 session PATCH 回归后再验证，不能只凭原生测试通过宣布交互完成。
- 修复只排除当前 run 的占位记录，不越过真正插入的其他轮次。两库真实聊天验证：先询问，用户答复后正确保存只含节点 1、2 和边 1→2 的子图；下一次修改重新询问。Neo4j 无效答复、FalkorDB 切换连接后答复均未修改本地图。证据 `chat-source-final-v2/`。
- 静态复核发现 `register_session`、`delete_graph_session` 只有 barrier、漏报图写入；实际模型工具目录确实暴露二者。共享策略补 `writes={"graph"}`，保留 barrier，不通过复制另一份工具黑名单保护。末次镜像的真实 `delete_graph_session` 调用已被挡住，以聊天询问而非删除会话，证据 `final-policy-dialogue/falkordb/lifecycle/`。
