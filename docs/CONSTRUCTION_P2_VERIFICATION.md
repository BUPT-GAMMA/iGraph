## 修复范围

- **自动构图后的业务属性编辑**：公共 preview/commit 和工作台按源记录的 `properties.data` 访问业务列。旧的顶层属性图保持兼容；`data`、`table`、点号等仍可作为完整业务列名。字段提取与转移使用现有当前属性节点/边表示，保留源记录关联，避免出现另一份用于验证的隐藏值。边上的转移属性可按业务别名查看和删除，冲突会原子拒绝。
- **重试时旧失败干扰新结果**：保留既有 `build_id` 和成功通知去重逻辑，并修复新发现的边界：POST 因网络/网关超时丢失响应后，前端仍记住旧失败，继续等待新进度或新结果。明确的参数拒绝会恢复操作按钮；有新 `build_id` 的失败和已观察到新进度后的旧协议失败可以正常结束等待。
- **SQLite 外键动作误拒绝**：按语句类型校验，允许建表中的合法 `ON UPDATE` / `ON DELETE` 动作。INSERT 保留显式查询、更新等限制；SQLite 授权回调拒绝建表查询、附加数据库、触发器和函数等受限操作，并兼容 SQLite 对多行 VALUES 的内部 SELECT 回调。

本次未新增依赖，未改变公共操作请求字段、图文档外层格式或修订号规则。
